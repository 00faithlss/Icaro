# Icaro Launcher 0.2.1

Parche de sincronización sobre 0.2.0. Actualiza tanto el servicio del anfitrión como el launcher cliente; el anfitrión no necesita instalar el launcher.

## Cambios

- Conserva la dependencia instalada si Modrinth fija otra versión y ambos JAR están identificados por hash. Publica el mod dependiente como archivo propio con un aviso, sin sustituir los archivos del servidor. Esta política no valida los rangos de Fabric ni garantiza la compatibilidad dentro del juego.
- Conserva las dependencias de cliente necesarias, propaga los archivos propios entre dependientes y evita volver a introducir dependencias exclusivas de servidor. Los pins contradictorios sin archivos instalados y las respuestas inconsistentes siguen bloqueando la publicación.
- Añade caché en memoria por hash, proyecto, versión y filtros: una hora para respuestas válidas y diez minutos para hashes desconocidos, con límites de 2048 entradas y 32 MiB. Conserva los resultados parciales y consulta los hashes nuevos mientras los anteriores sigan vigentes.
- Respeta las pausas de Modrinth ante 429 y aplica esperas crecientes. Los fallos de preparación dejan de repetir todas las consultas cada diez segundos; un cambio de archivos permite reintentar respetando la pausa del proveedor.
- Amplía de 128 a 512 el límite de resolución del cliente.

Consulta la [guía de sincronización](../sincronizacion-servidores.md) para iniciar el servicio y revisar los avisos.

## Validación y pendientes

Probada la publicación y sincronización con Surveyor 1.2.4 y Fabric API 0.116.17 reales, sin reemplazar la versión instalada. Las regresiones cubren caché parcial y negativa, límites de solicitudes, dependencias transitivas y ciclos, y conjuntos de 163 mods. El ejecutable Linux se recupera de un JAR inválido sin repetir el fallo cada diez segundos.

Falta validar la carpeta real del anfitrión, la conexión entre ambos equipos y la entrada al juego. La suite general mantiene un fallo previo de restauración de instancias con nombres Mundo/MUNDO en Linux.
